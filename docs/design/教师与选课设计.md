# 教师与选课设计

日期：2026年10月20日。

## 角色与课程归属

原 admin 账号更名为 teacher01，身份改为 TEACHER；新增 teacher02。当前仅有 TEACHER、STUDENT 两类角色。teacher01（教师一）负责高等数学、数据库系统原理；teacher02（教师二）负责单片机、数据结构、计算机网络。两者演示密码均为 123456。

两位教师均保留原管理端的学生账号创建、启停、重置密码能力。课程列表、课程分析、练习记录及练习结果限制在教师负责的课程内。教师界面沿用 /admin 路由以兼容既有页面，角色显示为“教师”。

## 新增关系

- course.teacher_id：必填，外键引用 app_user.id；每门课当前恰好有一名任课教师。初始化与教师业务逻辑保证对应角色为 TEACHER。
- course.is_open：0/1，由 CHECK 约束；当前五门课程均为 1。
- course_enrollment(student_id,course_id,joined_at)：学生与课程的多对多关系。student_id、course_id 构成联合主键，两列分别外键引用 app_user、course。学生身份由认证接口校验；请求不能指定其他学生作为加入对象。
- idx_enrollment_course(course_id,student_id)：支持课程成员计数与学生名单。

升级时一次性为 20 名现有学生建立 100 条选课关系。新增学生账号不会自动加入所有课程，可自行搜索加入。后续普通启动不会重新插入已退出的选课关系。

## 接口

| 接口 | 权限 | 行为 |
| --- | --- | --- |
| GET /api/courses | 已登录 | 学生的已加入课程，或教师负责的课程 |
| GET /api/student/courses/catalog?keyword= | 学生 | 按名称、描述、教师姓名搜索全部开放课程，返回教师、人数、题量与是否已加入；空词返回全部 |
| POST /api/student/courses/{id}/join | 学生 | 加入课程，重复加入幂等，未开放课程拒绝加入 |
| DELETE /api/student/courses/{id} | 学生 | 退课，重复退出幂等，不删除练习或答案 |

搜索词按字符串匹配，参数化查询，不把请求内容拼入 SQL。输入上限 100 字。加入与退出都锁定课程行，联合主键防止并发重复选课；创建练习同样锁定课程行并重新验证选课状态。

## 页面与数据访问

学生侧栏增加独立“我的课程”选项；已加入课程显示任课教师、题库数量、在课人数、学习入口与退课按钮。“加入课程”打开课程搜索弹窗。退课需要确认，加入后即时刷新列表。

课程列表、首页汇总、历史与错题列表均按当前选课过滤。退出期间不能开始练习、读取该课程题目、提交练习或访问其分析；学习数据保留，重新加入后可继续使用。退完全部课程时，练习、错题和分析页面显示加入课程引导。

共享 SQL 条件使用请求线程中的认证身份，过滤学生当前选课和教师课程归属；请求结束清除线程上下文。涉及显式课程编号、章节编号、练习编号的入口也在服务层校验权限，不能通过修改 URL 绕过。
