# 任教班级设计与验证

日期：2026年10月20日。

## 功能

教师侧栏新增“任教班级”，入口为 /admin/classes.html。教师可以按负责课程筛选班级，创建、编辑班级名称、学期、地点和备注，进入班级搜索学生、查看学习情况、批量添加学生或移出学生，并解散班级。

初始化时为五门课程分别建立一个“2024级教学一班”，每班包含该课程原有 20 名选课学生。教师一可管理两班，教师二可管理三班。每个教学班属于一门课程，教师身份通过课程归属确定，不在班级表冗余存储 teacher_id。

## 业务规则

- 教师只能访问自己负责课程下的班级。更换网址中的班级编号不能读取、修改、解散其他教师的班级或查看其学生。
- 创建班级时只能选择任教课程；班级创建后所属课程不可修改。
- 同一课程的未解散班级名称不能重复；解散后可以重新使用名称。
- 学生必须先选课才能加入该课程的教学班；添加界面仅显示账号启用、已经选课且尚未分班的学生。
- 同一名学生在一门课中最多加入一个教学班。转班流程为先从原班移出，再加入新班。
- 移出班级不退课、不删除作答或练习记录。退课会通过外键级联同步移除该课程的班级成员关系；重新选课后需由教师重新分班。
- 解散班级将其归档并清空当前班级成员，学生的选课和学习记录保留。归档班级不再出现在管理列表中。
- 批量添加采用事务，任意学生不满足条件时整批回滚。重复添加当前班级成员是幂等操作。成员修改先锁定课程和班级，再锁定选课关系，以协调并发退课和分班。

## 数据结构

teaching_class：id 主键；course_id 外键；name、semester、location、notes、archived、created_at、updated_at。生成列 active_name 仅对未归档班级返回名称，配合 UNIQUE(course_id,active_name) 实现有效班级名称唯一。CHECK 约束限制班级名称、学期非空白及 archived 为 0/1。

class_member：class_id、course_id、student_id、joined_at。PRIMARY KEY(class_id,student_id)，UNIQUE(student_id,course_id)。复合外键 (class_id,course_id) 引用 teaching_class(id,course_id)，避免跨课程分班；复合外键 (student_id,course_id) 引用 course_enrollment(student_id,course_id)，并设置 ON DELETE CASCADE，避免退课后遗留班级成员。加入后续课表与签到模块后，当前完整数据库共14张表，统一定义在sql/init.sql。

## 接口

| 接口 | 用途 |
| --- | --- |
| GET /api/admin/classes?courseId= | 本教师班级列表 |
| POST /api/admin/classes | 创建班级 |
| GET /api/admin/classes/{id} | 班级详情 |
| PUT /api/admin/classes/{id} | 编辑班级信息 |
| DELETE /api/admin/classes/{id} | 解散班级 |
| GET /api/admin/classes/{id}/students?keyword= | 搜索班级学生 |
| GET /api/admin/classes/{id}/candidates?keyword= | 搜索可添加学生 |
| POST /api/admin/classes/{id}/students | 批量添加 studentIds |
| DELETE /api/admin/classes/{id}/students/{sid} | 移出学生 |

接口沿用 /admin 路由，认证角色要求为 TEACHER，所有班级查询和修改都额外验证课程归属。
