# 多课程学习薄弱项分析系统需求文档

版本：1.5  
确认日期：2026年10月19日  
项目形式：浏览器访问的 Web 网站  
用途：数据库系统课程设计

## 1 项目目标

系统面向学生提供多课程练习、自动评分、错题复习和知识点薄弱项分析，面向管理员提供学生账号管理以及个人和整体学习情况查看功能。课程、章节、知识点和示例题目通过 SQL 脚本预先录入。

核心流程为：学生从预置课程中选择练习，系统随机抽题并打乱选择题选项，评分并保存记录，根据作答结果识别需要优先复习的知识点，学生再进行针对性练习。

项目应体现合理的数据库关系、完整性约束及有价值的数据加工，支持现场操作演示。分析采用明确、可解释的统计规则。

## 2 范围

### 2.1 第一版包含的功能

- 支持多门课程，各课程分别设置章节、知识点和题目。
- 支持学生和管理员两类账号。
- 支持单选题、多选题、判断题及自动评分。
- 支持按课程、章节或知识点选择练习，选择题量并随机抽题。
- 提供 25 套固定章节练习：每门课程 5 章，每章固定包含该章全部 20 道题。所有学生看到相同题目和题目顺序，仅选择题选项顺序随机。
- 支持作答记录、错题本、错题重练、个人统计和复习建议。
- 支持管理员查看所有学生的数据、整体统计及同一课程下的学生情况对比。
- 支持管理员创建、停用、重置学生账号。

### 2.2 第一版不包含的功能

不包含课程、章节、知识点和题目的新增、修改、删除、停用等管理功能，不采用题目版本或题目内容快照。固定章节练习通过题库预置，不实现教师发布流程。不包含简答题、人工批改、限时考试、班级管理、排行榜、跨课程综合能力评分、AI 出题或 AI 分析、支付和消息推送。暂不开发小程序、手机 App 或独立桌面客户端。

已确定采用 HTML、CSS、原生 JavaScript 编写前端，Nginx 部署前端网页，Java 编写后端，MySQL 存储数据，MyBatis 完成数据库访问，Maven 管理后端项目与依赖。技术栈保持简单。网站应支持在演示电脑本地启动并通过浏览器访问，不依赖公开上线才能完成演示。

| 功能 | 学生 | 管理员 |
| --- | --- | --- |
| 登录和修改本人密码 | 允许 | 允许 |
| 练习和提交答案 | 允许 | 第一版不提供 |
| 查看练习记录及答案解析 | 仅本人 | 所有学生 |
| 查看错题及薄弱项 | 仅本人 | 所有学生 |
| 查看个人统计 | 仅本人 | 所有学生，可选择学生查看 |
| 查看整体统计与学生对比 | 不允许 | 允许 |

## 4 账号管理

1. 学生不自行注册，由管理员统一创建账号，学号作为登录账号，学号不可重复。
2. 学号按字符串保存，保留可能存在的前导零。管理员创建账号时填写学号与姓名。
3. 学生初始密码为 `123456`，登录后可直接使用学习功能，修改密码为自愿操作。
4. 学生可以修改本人密码，需验证原密码；新密码不得为空或继续使用默认密码，长度至少为 6 位。
5. 管理员可将学生密码重置为 `123456`，重置后学生可直接登录，无需修改密码。
6. 停用账号不得继续访问受保护功能；停用不删除学生历史学习记录。
7. 密码采用加盐哈希保存，不保存或展示明文密码。管理员只能重置密码，不能查看原密码。
8. 管理员账号由系统初始化提供，不开放管理员自行注册入口。

## 5 课程与题库

### 5.1 内容组织

课程下设章节，章节下设知识点。每道题归属一门课程和一个章节，并关联该章节下一个或多个知识点。课程、章节、知识点和题目的关联必须保持一致，不能跨课程或跨章节误关联。

当前课程包括高等数学、数据库系统原理、单片机、数据结构、计算机网络。每门课程 5 章，每章 20 题，共 500 题；每章设置两个知识点，每个知识点对应 10 题，覆盖单选、多选、判断。具体章节与知识点见固定练习题库目录.md。

至少准备一个知识点关联 3 道以上不同题目，并准备部分多知识点题目，以便演示样本不足、掌握等级和知识点关联分析。题目、标准答案及解析应正确，可自行编写简单示例题。

### 5.2 题目要求

题目包含题型、题干、选项、标准答案、解析、所属课程、章节和知识点，每道题只保存一份内容。

- 单选题必须且只能有 A、B、C、D 四个选项，四项内容均不能为空，且只有一个正确答案。
- 多选题必须且只能有 A、B、C、D 四个选项，四项内容均不能为空，且至少有两个正确答案，即正确答案数量为 2 至 4 个。标准答案为有效选项组成的集合。
- 判断题提供“正确”和“错误”两个选项，仅一个正确答案。
- 每道题至少关联一个有效知识点；正确答案不能引用不存在的选项。
- 第一版题干与解析使用文本，暂不要求公式编辑器、图片上传或富文本。

### 5.3 预置题库与选项随机排列

网站不提供题库维护页面或写入接口。课程、章节、知识点和题目预先录入，演示期间作为固定数据使用，不设计修改历史题目的处理流程。

单选、多选在开始练习时随机排列四个选项，再按显示位置标为 A、B、C、D。每条练习明细仅额外保存该次排列映射，不复制题干或选项文本。排列在本次练习中保持不变，历史详情还原该次排列。随机结果允许与原顺序相同。

标准答案对应题库中的原始选项，后端使用保存的映射将学生所选显示字母转换为原始选项后评分。结果页面的正确答案也按该次显示顺序转换。判断题固定显示“正确、错误”，不打乱。

## 6 练习与评分

### 6.1 普通练习

1. 学生选择课程，可进一步选择章节或知识点，填写 1 至 50 的整数题量，默认 5 题。
2. 系统从符合筛选条件的预置题目中随机抽取，同次练习不重复抽取同一道题，并生成本次选择题的选项排列。
3. 可用题目不足时，按实际数量出题并提示；没有可用题目时不创建空练习。
4. 学生在提交前可修改选项，练习过程中不展示标准答案和解析。
5. 提交前提示未作答题目数量，由学生确认提交。
6. 提交后显示得分、正确率、逐题作答、标准答案和解析，记录变为只读。

第一版不要求跨设备续答或草稿恢复。未提交练习不进入成绩、错题和薄弱项统计。

### 6.2 评分规则

- 每题 1 分，不设置难度权重，总分等于本次题目数量。
- 单选和判断题与标准答案一致得 1 分，否则为 0 分。
- 多选题所选集合与标准答案集合完全一致得 1 分，漏选、错选均为 0 分，选择顺序不影响结果。
- 未作答题目得 0 分，计入本次已提交练习的错误题目及知识点统计。
- 练习正确率 = 正确题数 ÷ 本次总题数 × 100%。
- 评分由后端完成，不接受客户端直接上传的成绩作为最终结果。
- 同一次练习重复提交不能产生重复记录或重复统计。

### 6.3 固定章节练习

开始练习页面提供“固定章节练习”和“自主随机练习”两个入口。固定练习按课程显示 5 个章节，展示题量、已完成次数、最近成绩与结果入口。每次开始均创建独立练习，可重复完成。

固定练习按该章节题目 ID 的稳定顺序出题，始终为 20 题，不随机抽题或打乱题目顺序；单选和多选的选项仍分别随机排列。自主随机练习保留按范围和题量抽题的功能，使用当前题库。

### 6.4 本轮演示数据调整

仅为 20240001 生成 25 套完整章节作答，共 500 题，各知识点均覆盖 10 道不同题，提供不同掌握等级用于演示。原先练习采用归档保留，从该学生当前历史、统计和错题中排除。其他 19 名学生的原记录与账号不变，暂不生成或替换其数据。

旧题库从新课程目录与抽题范围隐藏，仍保留供原作答详情引用。其他学生已作答的旧知识点在分析中标记为“旧题库”，不与新知识点混合。

## 7 错题复习

已提交练习中的错误题目自动收录错题本，包括未作答题目。相同题目不重复展示为多个错题条目，但保留每次作答记录和错误次数。

学生可按课程、知识点筛选错题并发起重练。最近一次作答正确时显示“最近已答对”，不删除之前的错误记录；再次答错则更新最近作答状态。

错题重练从原题库取出对应题目，重新生成选择题选项排列，按普通练习规则评分并计入学习统计。

## 8 薄弱项分析

### 8.1 分析口径

仅使用已提交练习的记录，按课程和知识点分别分析。

**累计表现**使用全部已提交作答，重复作答均计入，展示累计答题次数、正确次数和正确率，反映长期练习情况。

**近期掌握情况**按学生与题目去重，每道题仅取最近一次已提交作答，计算各知识点的正确率。此处“近期”指最近一次结果，不采用最近若干天的时间窗口。界面应说明该口径。

同一道题关联多个知识点时，该次结果对每个关联知识点各贡献一次正确或错误；课程整体统计仍只计算一道题，不能将知识点统计相加作为课程总题数。不同课程分别统计，不生成跨课程综合能力分数。

同一道题即使选项排列不同，统计时仍按题目 ID 认定为同一题，不把不同排列计为不同题目。

### 8.2 等级规则

| 最近作答覆盖的不同题目数量 | 正确率 | 展示结果 |
| --- | --- | --- |
| 0 道 | 不计算 | 暂无练习记录 |
| 1 至 2 道 | 展示实际值 | 练习不足，暂不判断等级 |
| 至少 3 道 | 低于 60% | 优先复习 |
| 至少 3 道 | 大于等于 60% 且低于 80% | 需要巩固 |
| 至少 3 道 | 大于等于 80% | 掌握较好 |

等级使用未四舍五入的数值判断，百分比显示可保留一位小数。上述阈值为课程设计中的演示规则，用于辅助复习，不作为精确能力测评结论。

### 8.3 复习建议

按“优先复习”“需要巩固”的顺序展示知识点；同等级内优先展示正确率较低的知识点，再按错误题数降序排列。建议应列出知识点、题量、正确率和对应练习入口。

练习不足的知识点单独提示补充练习，不强行列入薄弱项等级。没有记录时引导开始练习，不展示虚构成绩。

## 9 数据展示

### 9.1 学生学习中心

- 各课程练习情况，包括已提交练习次数、累计答题次数及累计正确率。
- 按课程查看知识点近期掌握情况、练习量及复习建议。
- 练习历史与详情，包括时间、课程、题数、得分和正确率。
- 按提交时间展示同一课程的练习正确率变化，作为练习表现趋势。
- 错题列表、筛选和重练入口。

不同练习题目及难度可能不同，趋势展示应标注题量，不将变化直接解释为严格的能力提升。

### 9.2 管理后台

- 查看学生总数、启用状态及各课程实际参与练习的学生人数。
- 按课程查看提交次数、答题次数、整体正确率和知识点情况。
- 整体累计正确率按正确作答总次数除以作答总次数计算，不直接平均学生百分比。
- 共性薄弱项按各学生的题目最近一次结果汇总，展示参与人数、学生与题目的有效组合数量及正确率。
- 整体知识点参与人数不足 3 人，或有效组合不足 3 条时，标注样本不足，不给出整体掌握等级；其余沿用个人等级的正确率阈值。
- 可按学生查询其课程统计、练习详情、错题和薄弱项。
- 同一课程下可并列查看学生正确率、题量及参与情况，不生成排行榜。

## 10 数据与完整性要求

核心数据包括账号、课程、章节、知识点、题目、题目与知识点关联、练习及练习明细。四个原始选项保存在题目中，选项排列和作答结果保存在练习明细中，不设置题目版本表。

应至少体现以下约束：

- 实体完整性：各实体主键唯一且非空。
- 参照完整性：章节引用有效课程，知识点引用有效章节，作答引用有效学生及练习，关联关系不能悬空。
- 用户定义完整性：学号唯一、角色有效、题型有效、题量为正整数、答案符合题型、得分处于合法范围、题目关联范围一致。
- 删除约束：被历史数据引用的记录不能直接删除而破坏历史。
- 提交一致性：练习状态变更、逐题结果、总成绩的保存应保持一致，失败时不能留下部分提交结果。

数据库约束与后端业务校验应共同保证数据有效性，不能只依赖页面校验。

## 11 页面范围

学生端包括登录、自愿改密、学习首页、课程练习选择、答题、结果详情、练习历史、错题本、薄弱项分析和账号设置页面。

管理员端包括统计首页、学生管理、学生学习详情和账号设置页面，不提供课程或题库维护页面。页面可合理合并，不要求每项功能独立占用一个页面。

界面以电脑浏览器使用为主，提供清楚的导航、字段提示、空状态及操作成功或失败反馈。列表提供必要的筛选与分页，停用、删除和重置密码等操作应有确认提示。

## 12 演示数据

提供一个管理员账号及至少三个学生示例账号，学生学号不同，初始密码规则一致。准备五门示例课程及少量题目，并安排正确率不同、重复答题、未作答、多选漏选等示例场景。

分析演示可通过预置示例历史或现场练习完成。预置记录必须与评分和统计规则一致，标识为演示数据，不使用真实学生隐私信息。

| A17 | 尝试保存无效答案或错误关联 | 后端拒绝，数据库不产生无效关系 |
| A18 | 检查预置单选题或多选题 | 必须有且仅有 A、B、C、D 四个非空选项；单选正确答案恰好一个，多选为 2 至 4 个 |

## 14 技术路径

### 14.1 已确定的技术栈

| 层次 | 技术 | 职责 |
| --- | --- | --- |
| 前端 | HTML、CSS、原生 JavaScript | 页面结构、样式、交互及调用后端接口 |

### 14.2 架构与项目组织

Spring Boot 框架已确认。架构参考 `D:\JavaWeb-AI-Study` 中的 Tlias 项目，采用适合课程设计的单模块分层组织。以下组织及登录细节为本项目的设计基线，后续设计可在不改变业务需求的前提下调整。

- 后端采用 Spring Boot 与 Spring MVC，按 Controller、Service、Mapper 分层；MyBatis 使用 XML 编写 SQL，便于课程报告和答辩解释。
- 前端采用多个 HTML 页面及共享 CSS、JavaScript 文件，通过 Fetch 调用 JSON 接口。
- 浏览器统一访问 Nginx；静态页面由 Nginx 返回，`/api/` 请求转发至 Java 后端，前后端使用同一访问入口。
- 登录采用 JWT，前端通过 `Authorization: Bearer <token>` 请求头携带令牌，不使用 Cookie 自动携带登录凭证。后端统一校验签名、有效期、账号启用状态、登录版本及角色，并在业务中校验数据归属。
- 数据表采用 InnoDB 与 utf8mb4，数据库结构和演示数据使用 SQL 脚本初始化，关键提交操作使用事务。
- 默认本地单机部署，交付前端文件、后端可运行 JAR、SQL 初始化脚本、Nginx 配置和启动说明，不将 Docker 作为运行前提。
- Java、Spring Boot、MyBatis 相关依赖、MySQL、Maven 和 Nginx 的具体版本，在检查开发及演示环境后锁定并记录，避免依赖版本不兼容。

### 14.3 参考项目的沿用与精简

主要参考 `JavaWeb-AI-Project02/tlias-web-management` 的单模块分层；`JavaWeb-AI-Project03` 中的父工程、实体模块和工具模块不另行拆分，均在本项目后端中按包组织。

沿用以下结构：

- `controller`：接收 HTTP 请求和返回结果，不直接编写 SQL。
- `service` 与 `service/impl`：业务接口和实现，负责评分、统计、权限归属校验和事务边界。
- `mapper` 与资源目录中的 Mapper XML：数据库访问接口及 SQL。
- `pojo`：实体、请求参数和响应数据对象，区分可写入字段与对外返回字段，避免暴露密码哈希或提交前的标准答案。
- `config`、`interceptor`、`exception`、`utils`：配置、登录与角色检查、统一异常处理及必要工具。
- 统一响应包含 `code`、`msg`、`data`，分页响应包含 `total`、`rows`。未登录、无权限等场景同时返回相应 HTTP 状态。
- 多表提交操作使用 `@Transactional`，SQL 参数使用 MyBatis 参数绑定。

为控制复杂度，不引入参考项目中的阿里云 OSS、自定义 Starter、Maven 私服、独立公共模块及自定义 AOP 操作日志。分页先采用 MySQL `LIMIT` 与总数查询，不额外引入 PageHelper。日志使用 Spring Boot 默认日志体系，Lombok 仅在有助于减少实体样板代码时使用。

沿用参考项目的 JWT 登录思路，具体规则如下：

- 登录成功后签发有效期为 2 小时的访问令牌，采用固定到期时间，不因操作自动延长；不增加刷新令牌机制，过期后重新登录。
- 令牌包含用户 ID、角色、登录版本号及签发和过期时间，不包含密码、密码哈希或其他不必要的个人信息。
- 用户表保存登录版本号。每个受保护请求均查询当前账号状态与版本，校验令牌角色与数据库角色一致，不能只验证签名便放行。
- 修改密码、管理员重置密码、退出登录、停用账号或修改角色时递增登录版本号，使该账号此前签发的令牌全部失效。重新启用账号也不恢复旧令牌。
- 第一版允许同一账号多处登录，但以上失效操作对该账号所有已登录位置生效。界面退出操作应请求后端，再清除前端令牌。
- 不设置首次或重置后的强制改密限制；学生可直接使用默认密码登录。自愿改密后清除旧令牌并重新登录。
- 前端使用 sessionStorage 保存令牌，关闭页面标签后需重新登录；不实现记住登录功能。令牌过期返回 401，前端提示登录失效并引导重新登录。
- 练习提交前若登录失效，提示重新登录，本版不承诺恢复未提交答案；页面应明确提醒，避免将未提交内容视为已保存。
- JWT 密钥通过外部配置提供，不写入前端或提交到代码仓库。通过后端权限检查阻止学生访问管理员功能或其他学生数据。

上述方案不依赖 Redis 或令牌黑名单，账号查询同时承担停用与令牌撤销检查；适合本项目单体部署规模。

参考项目 Project02 的 POM 声明 Java 17、Spring Boot 4.0.5、MyBatis Starter 4.0.1；Project03 的父工程另设 Java 编译目标 25，且存在独立指定其他版本 Spring 依赖的配置。本项目不直接复制整份 POM，后续统一 Java 编译目标，依赖尽量遵循 Spring Boot 的版本管理，仅保留实际需要的依赖。此处记录的是静态阅读结果，不代表参考项目已通过本次构建验证。
